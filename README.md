# Analysis of the Hardware Generation Process via HLS: From Code to RTL

This repository contains the codes and files associated with the paper **"Analysis of the Hardware Generation Process via HLS: From Code to RTL"**. The study analyzes how algorithms written in C/C++ are translated into hardware structures (RTL) using High-Level Synthesis (HLS) tools, specifically Xilinx Vitis/Vivado 2024.2.

## Repository Structure

The repository is organized into three main directories, reflecting the development, synthesis, and validation stages discussed in the paper:

### 1. `src/` (C/C++ Source Code)
This folder contains the original high-level algorithms (C/C++) and their respective testbenches (`_tb.cpp`). These codes serve as the input (starting point) for the HLS process. The algorithms are divided into:
*   **`arith-prog-sum/`**: Deterministic $O(1)$ complexity algorithm for the Sum of an Arithmetic Progression (AP).
*   **`factorial/`**: Iterative algorithm for Factorial calculation.
*   **`sqrt/`**: Iterative algorithm for Integer Square Root calculation.
*   **`factorial-sqrt/`**: Algorithm that combines the Factorial calculation followed by the Square Root (demonstrating the nesting and integration of FSMs).

### 2. `hls/` (HLS-Generated RTL)
Here you can find the Verilog (`.v`) files that were **automatically generated** by the Xilinx Vitis HLS compiler from the codes in the `src/` folder.
*   Contains the main modules, operation submodules (like multipliers), and dataflow control files.
*   These files are the main focus of the analysis performed in the paper, mapping how C/C++ loops and conditions are transformed into Finite State Machines (FSMs) or linear pipelines.
*   Also includes the testbench files (`_tb.v`) used for behavioral simulation.

### 3. `rtl/` (Manual/Refactored RTL Implementations)
This folder contains RTL modules written (or isolated) manually in Verilog and it was not included in the paper.
*   After analyzing the circuit generated by HLS for the **Arithmetic Progression Sum**, a manual version was created to validate the understanding of the datapath and control unit.
*   Includes classic hardware infrastructure submodules (such as `mux_2x1.v` and `register.v`), the control unit (`_cu.v`), and the datapath (`_dp.v`).
